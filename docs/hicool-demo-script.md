# HICOOL 三个 Subagent、四领域连续演示主线

## 演示目标

在同一个 Staix 主会话中连续提出四类业务请求。竞赛模式保持 MTClaw Router 开启，用户不手动 `@` 子智能体、不切换专业模式。每一轮都必须展示 Function Router 的自动选择、pi-agent 的真实子任务执行、外部能力调用和当前智能体回答模型的最终回复。

四个演示领域由三个专业 Subagent 覆盖：

| 演示领域 | 预期 Subagent |
|---|---|
| 企业主体身份核验 | `enterprise_due_diligence` |
| 企业经营、信用与司法风险 | `enterprise_due_diligence` |
| 法规和类案研究 | `legal_research` |
| 合同相对方与合同风险审查 | `contract_counterparty_risk_review` |

## 前置条件

- 当前智能体已配置可用的最终回答模型。
- MTClaw 使用独立 Router 模型，Router 健康检查通过。
- Staix 中三个子智能体均已绑定正确的模型、Tool/MCP、Skill 和知识。
- 企业尽调已接入获授权的 QCC 能力。
- 法规和案例来源允许现场查询与展示。
- 准备一份包含明确相对方的测试合同，且不含真实敏感数据。

## 第一轮：企业主体身份核验

示例请求：

> 请核验合同中的乙方企业是否真实存续，确认企业全称、统一社会信用代码、法定代表人和注册地址。如果存在重名主体，请先让我确认，不要自行合并。

预期行为：

- Router 自动选择 `enterprise_due_diligence`。
- pi-agent 子智能体调用 Staix 已配置的 QCC MCP/CLI 或获授权 API。
- 发生重名时进入 `needs_confirmation`，用户确认后继续同一任务。
- 输出企业身份字段、来源、查询时间和数据缺口。

## 第二轮：企业经营、信用与司法风险

示例请求：

> 继续检查刚才确认的企业是否存在经营异常、严重违法、失信、被执行、重大诉讼或其他可能影响履约的风险，并按高、中、低分级。

预期行为：

- Router 结合连续会话上下文再次选择 `enterprise_due_diligence`。
- 子智能体复用已确认的主体标识，不重新猜测企业。
- 区分数据源原始事实、规则归类和模型判断。
- 输出风险等级、理由、来源、查询时间和未覆盖范围。

## 第三轮：法规和类案研究

示例请求：

> 如果对方迟延交付并拒绝退款，请研究可能适用的现行法规和相似案例。区分法律、司法解释、指导性案例和普通裁判文书，并说明哪些结论只是参考。

预期行为：

- Router 自动选择 `legal_research`。
- pi-agent 子智能体调用法规库、案例库、知识或浏览器能力。
- 对法规标记效力层级和时效性，对案例说明事实及争点相似度。
- 输出支持与不支持用户立场的材料、来源和适用限制。

## 第四轮：合同相对方与合同风险审查

示例请求：

> 现在站在我方采购方立场审查这份合同。结合前面的企业风险和法律研究，检查付款、交付、验收、退款、违约、解除和争议解决条款，给出风险等级、原文定位和可直接替换的建议条款。

预期行为：

- Router 自动选择 `contract_counterparty_risk_review`。
- 合同审查 Subagent 读取当前会话附件和已确认的审查立场。
- 必要时自动编排企业尽调和法规类案研究，而不是让用户再次手动调用。
- 每个风险项包含合同原文定位、外部证据、判断理由和修改建议。
- 外部查询失败时返回 `partial` 并说明对审查结论的影响。

## 现场必须展示

- Staix 主会话和连续四轮历史正常保存。
- 每轮请求均经过 MTClaw，而非仅显示 Router 已开启。
- Router 选择的 Subagent、选择理由和路由耗时。
- pi-agent 主会话与子任务的关联。
- QCC、法规库、案例库、附件或其他能力的真实调用。
- wrapper 输入输出合同或标准 tool-call 委托记录。
- 当前智能体回答模型 ID 与最终回答调用。
- 关键结论对应的数据来源、查询时间和合同原文定位。
- 超时、无数据、权限不足等失败能够明确回传和回退。
- Router、应用和审计日志中不出现真实 API Key、Authorization 或 Token。

## 演示失败判定

出现以下任一情况，不应视为通过：

- 用户必须手动选择或 `@` Subagent。
- Router 只经过接口但没有做出可证明的专业路由决策。
- wrapper 返回硬编码业务结果，未调用 pi-agent 子智能体或真实能力。
- pi-agent 的权限、附件、工作区或会话系统被绕过。
- 最终回答由 Router 模型替代当前智能体回答模型生成。
- 查询失败后生成无法回溯的企业信息、法规、案例或合同原文。

## 量化记录

演示和赛前回归至少记录：

- 四领域 Router 命中率。
- 三个 Subagent 的任务完成率。
- Router、子智能体、外部能力和最终回答各阶段耗时。
- 来源完整率和合同风险原文定位率。
- 歧义确认、部分成功、失败回退和取消是否符合统一合同。
