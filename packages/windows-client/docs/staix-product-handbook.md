# Staix 石斧智能体产品使用手册

面向潜在用户、投资人和合作伙伴的产品介绍与使用指南。

## 1. 产品概述

Staix 石斧智能体是一款面向企业业务场景的本地桌面智能体客户端。产品基于 Pi agent core 构建，通过图形化界面把大模型、企业知识、业务工具、文件工作区和审计记录组织在一起，帮助用户完成文档处理、信息抽取、规则校验、报告生成和业务流程自动化。

Staix 的设计目标不是让业务用户学习命令行或开发工具，而是把智能体能力包装成可配置、可审计、可复用的业务工作台。用户选择一个工作区，配置模型和业务能力后，可以直接以自然语言向智能体发起任务，由智能体读取资料、调用工具、处理文件并输出结果。

## 2. 适用对象

Staix 适合以下外部或企业内部角色了解和使用：

- 业务团队：产品经理、运营、法务、财务、风控、交付和专业业务人员。
- 管理者：希望评估 AI 智能体在企业内部落地价值的业务负责人。
- 技术团队：需要把大模型、内部 API、工具和业务知识封装给业务用户使用的工程团队。
- 合作伙伴：希望围绕 OCR、合同审查、知识库、审批、企业系统集成等场景共同建设解决方案的生态伙伴。
- 投资人：关注智能体产品形态、企业部署路径、数据安全和商业化场景的外部评估者。

## 3. 核心价值

### 3.1 面向业务用户，而不是只面向开发者

Staix 使用桌面图形界面承载智能体能力。用户不需要理解智能体运行时、命令行参数、代码仓库结构或工具调用协议，只需要选择工作区、配置业务能力、上传或引用文件，并用自然语言描述任务。

### 3.2 本地优先，降低企业落地阻力

第一版以本地桌面客户端为核心形态。配置、会话、日志、prompts 和生成产物默认保存在本地，适合企业在早期试点阶段控制数据边界、降低云端账号体系和集中化平台建设成本。

### 3.3 可配置模型与业务能力

Staix 支持多种模型接入方式，包括官方 API Key、OpenAI 兼容模型、本地模型和未来扩展 Provider。业务能力以 Tool、Skill、HTTP API、MCP、本地命令和浏览器能力等形式配置，并以“业务能力”而不是“脚本命令”的方式展示给用户。

### 3.4 可审计的智能体执行过程

智能体会话、工具调用、文件访问、模型交互和业务动作可以写入审计日志。审计记录包含时间、会话、工作区、能力名称、输入输出摘要、访问文件、网络目标、批量状态、成功失败状态和错误信息，便于企业复盘、合规检查和问题定位。

### 3.5 可扩展的智能体底座

Staix 使用 Pi agent core 作为内置智能体内核，并通过 Agent Adapter 封装运行时细节。这个架构允许客户端先保持简单稳定，同时为未来升级内核、替换执行引擎、接入企业协议和扩展子智能体能力预留空间。

## 4. 产品架构

Staix 采用本地桌面客户端加内置智能体引擎的架构：

```text
Electron Desktop UI
  -> Agent Adapter
    -> Embedded Pi agent core
      -> Model Providers / Tools / Skills / Files / APIs
```

主要模块包括：

- 桌面客户端：基于 Electron、React 和 TypeScript 构建，提供工作台、配置中心、日志查看和会话界面。
- 智能体内核：基于 Pi agent core，负责任务推理、上下文组织、工具调用和会话执行。
- 适配层：封装客户端和智能体内核之间的 RPC 通信，避免界面层直接依赖底层协议。
- 配置中心：管理模型、智能体、业务能力、上下文压缩、变量和运行时设置。
- 工作区服务：限制智能体在用户选择的 workspace 中读取、新建和编辑文件。
- 审计日志：记录工作区选择、会话启动、模型请求、工具调用、能力执行和文件访问。

## 5. 主要功能

### 5.1 工作区管理

用户可以选择一个本地项目文件夹作为工作区。智能体在该工作区内读取资料、浏览文件、生成结果和保存产物。

工作区能力包括：

- 选择本地文件夹作为任务空间。
- 浏览工作区文件列表。
- 预览小型文本文件。
- 把工作区作为文件权限边界。
- 对工作区选择和文件访问写入审计日志。

默认原则是优先在副本上处理文件，避免直接修改原始材料。涉及工作区外文件时，应由用户主动选择或明确授权。

### 5.2 智能体会话

用户可以在桌面客户端中启动智能体会话，以自然语言提交任务。智能体结合当前工作区、已配置模型、知识内容、任务模板和业务能力执行工作。

会话能力包括：

- 新建和停止智能体会话。
- 发送用户消息并接收智能体回复。
- 支持图片、文本、文档和普通文件作为会话附件。
- 图片附件可在视觉模型支持时作为视觉输入。
- 展示任务执行进度、成功或失败状态。
- 记录模型请求上下文、请求载荷和模型响应。

### 5.3 模型配置

Staix 提供模型档案管理能力，用于接入不同大模型服务。

模型配置包括：

- Provider 名称和展示名称。
- 模型 ID。
- API 类型，例如 OpenAI Responses、OpenAI Completions、Anthropic Messages、Google Generative AI。
- Base URL。
- API Key 环境变量或密钥配置。
- 默认思考等级。
- 传输方式。
- 超时时间和重试次数。
- 文本和视觉输入能力。
- 上下文窗口和最大输出长度。
- 输入、输出和缓存价格字段。
- 联通测试状态。
- 绑定到指定智能体。

支持的接入方向包括：

- 官方 API Key Provider。
- 国内外 OpenAI 兼容模型服务。
- 本地 OpenAI 兼容服务，例如 Ollama 和 LM Studio。
- 自定义 models.json。
- 未来通过扩展注册 Provider。

### 5.4 智能体配置

Staix 支持配置多个智能体。每个智能体可以拥有独立角色、目标、流程、输出格式、约束、术语、知识、任务模板、可用模型和可用业务能力。

智能体配置包括：

- 智能体名称和描述。
- 角色、目标、工作流程、输出格式和约束。
- 术语说明。
- 任务模板。
- 知识条目。
- 可用模型和默认模型。
- 可用业务能力。
- 主智能体和子智能体关系预留。

这种设计适合把同一套底层能力包装成不同业务助手，例如 OCR Prompt 优化助手、合同审查助手、财务核对助手或知识库问答助手。

### 5.5 业务能力配置

Staix 把工具和技能统一抽象为业务能力，避免向业务用户暴露底层脚本、命令和协议细节。

业务能力类型包括：

- Tool：智能体可调用的工具。
- Skill：带有使用说明、边界和流程的智能体技能。
- HTTP API：企业内部或外部接口。
- MCP：通过 MCP 服务暴露的工具能力。
- Browser：浏览器操作能力。
- Command：本地命令能力。
- Other：其他扩展能力。

业务能力配置包括：

- 能力名称、分类、标签和说明。
- 适用场景和不适用场景。
- 触发方式：智能体调用、手动触发、工作流触发或组合触发。
- 执行方式：HTTP、命令、内置能力、MCP 或手动占位。
- 输入和输出 schema。
- 认证、请求头、Token 环境变量。
- 超时、重试和联通状态。
- 成本策略和是否需要确认。
- 可使用该能力的智能体。

典型能力包括 OCR 验证、批量样本评估、Prompt 版本管理、合同文本抽取、合同审查清单执行、企业主体查询和报告生成。

### 5.6 知识与任务模板

Staix 支持给智能体配置知识条目和任务模板。

知识条目可以是：

- 业务规则说明。
- 审查清单。
- 字段定义。
- 术语表。
- 操作规范。
- AGENTS.md 风格的智能体行为说明。

任务模板可以沉淀常用工作流，例如：

- “优化一组 OCR 字段提取 prompt”。
- “对合同进行审查并输出风险清单”。
- “根据样本和标准答案生成准确率报告”。
- “读取项目资料并生成客户交付说明”。

### 5.7 审计日志

Staix 从第一版开始重视审计能力。由于智能体在任务授权后可能自动读取文件、调用 API、运行命令和批量执行操作，审计日志是企业落地的基础能力。

审计日志至少覆盖：

- 时间戳。
- 会话 ID。
- 任务或工作流 ID。
- Workspace 路径。
- Tool 或 Skill 名称。
- 业务动作名称。
- 输入摘要和输出摘要。
- 完整输入和输出。
- 读取、新建或编辑的文件。
- 网络请求目标或企业 API 目标。
- 是否批量执行。
- 成功或失败状态。
- 失败错误信息。
- 关联迭代轮次。

审计日志可用于复盘智能体行为、定位失败原因、证明执行边界、评估业务效果和支撑企业治理。

### 5.8 自动更新与本地运行

Staix 桌面客户端预留自动更新能力，可检查新版本、下载更新并安装。第一版内置固定版本的 Pi agent core，用户不需要单独安装智能体内核。

未来版本可支持：

- 智能体内核版本检测。
- 兼容范围校验。
- 用户主动选择内核更新。
- 回滚到内置版本。
- 更新失败恢复。

## 6. 典型场景

### 6.1 OCR Prompt 优化

这是第一版优先场景。目标用户通常是产品经理、解决方案人员或负责 OCR 质量优化的业务人员。

业务流程：

1. 用户选择包含样本图片、字段说明和标准答案的工作区。
2. 用户定义需要 OCR 提取的字段。
3. 智能体读取工作区内知识文件、prompts 和规则说明。
4. 智能体结合视觉模型生成或优化提取 prompt。
5. 智能体调用已配置的 OCR 或验证接口。
6. 用户可执行单次验证或批量验证。
7. 智能体对比提取结果和人工标准答案。
8. 智能体计算准确率并分析失败样本。
9. 智能体提出下一轮 prompt 优化建议。
10. 用户确认是否继续迭代或定稿。

输出结果：

- 最终 prompt。
- 验证结果。
- 准确率报告。
- 失败样本分析。
- 迭代记录。

### 6.2 合同审查

第二优先场景是法务合同审查。用户指定一个或多个待审合同后，智能体基于合同审查规则、知识文件和审查清单执行审查。

业务流程：

1. 用户选择合同文件所在工作区。
2. 用户配置或选择合同审查智能体。
3. 智能体读取合同、审查规则和知识文件。
4. 智能体识别合同类型、条款类型和审查事项。
5. 智能体匹配高风险条款、不一致内容和缺失事项。
6. 智能体生成审查结果、风险说明和修改建议。
7. 结果优先写入合同副本，或以清晰的批注表、Markdown 报告、表格文件输出。

输出结果：

- 合同审查报告。
- 风险条款清单。
- 修改建议。
- 审查依据。
- 可复查的处理记录。

### 6.3 企业知识辅助与报告生成

Staix 可将企业内部规则、项目资料、业务说明和外部接口组合起来，用于生成交付文档、客户说明、调研报告、风险分析和运营复盘。

适用任务：

- 基于资料生成客户交付手册。
- 汇总多个文件并形成结构化报告。
- 根据企业知识库回答业务问题。
- 调用内部接口补充数据。
- 生成可审计的处理过程和结果文件。

### 6.4 业务流程编排

通过任务模板、业务能力和智能体配置，Staix 可以把复杂流程封装成可重复执行的业务工作流。

示例流程：

- 读取输入资料。
- 校验字段完整性。
- 调用企业 API。
- 批量处理样本。
- 生成中间结果。
- 对失败样本分类。
- 输出报告。
- 等待用户确认后继续下一轮。

## 7. 基本使用流程

### 7.1 第一次使用

1. 启动 Staix 桌面客户端。
2. 选择一个本地工作区。
3. 打开配置中心。
4. 配置至少一个模型。
5. 测试模型联通状态。
6. 配置或选择一个智能体。
7. 根据需要配置业务能力。
8. 回到工作台，启动会话并输入任务。

### 7.2 配置模型

1. 进入配置中心的模型管理页面。
2. 新建模型档案。
3. 选择 Provider 或接入方式。
4. 填写模型 ID、Base URL、API Key 环境变量或密钥。
5. 选择模型能力，例如文本或视觉。
6. 设置上下文窗口、最大输出长度、超时和重试。
7. 绑定可使用该模型的智能体。
8. 执行联通测试。
9. 保存配置。

### 7.3 配置业务能力

1. 进入配置中心的业务能力页面。
2. 新建能力。
3. 选择能力类型，例如 Tool、Skill、HTTP API、MCP、Browser 或 Command。
4. 用业务语言填写能力说明。
5. 填写适用场景和不适用场景。
6. 配置接口、命令、MCP 服务或能力内容。
7. 设置认证、超时、重试、输入输出 schema。
8. 绑定可使用该能力的智能体。
9. 测试联通状态。
10. 保存配置。

### 7.4 使用智能体处理任务

1. 在工作台选择当前智能体。
2. 确认工作区和模型配置正确。
3. 上传或引用需要处理的文件。
4. 输入任务说明。
5. 查看智能体进度、回复和中间结果。
6. 根据结果继续追问、要求修改或确认定稿。
7. 在工作区中查看生成文件。
8. 在审计日志中查看执行记录。

## 8. 权限与安全边界

Staix 的默认权限模型围绕用户选择的工作区展开：

- 智能体可以读取用户选择的 workspace 内文件。
- 智能体可以在 workspace 内新建文件。
- 智能体可以在 workspace 内编辑文件。
- 智能体应优先编辑副本，而不是直接编辑原始文件。
- 智能体可以执行本地命令和调用外部接口，但界面应以业务动作展示执行过程。
- 读取 workspace 外部文件应由用户明确选择或授权。
- 每次工具调用和关键业务动作应记录审计日志。

对于企业客户，建议在试点阶段明确以下边界：

- 哪些目录可以作为工作区。
- 哪些模型 Provider 可以使用。
- 哪些内部 API 可以开放给智能体。
- 哪些能力需要人工确认。
- 哪些数据不得发送给外部模型。
- 审计日志保存周期和查看权限。

## 9. 部署与集成方式

### 9.1 本地桌面部署

Staix 第一阶段以 Windows 桌面客户端为主要交付形态，适合在单个业务用户、试点团队或小范围 PoC 中快速落地。

特点：

- 用户本地安装。
- 本地保存配置和日志。
- 内置智能体运行时。
- 可连接外部模型和企业 API。
- 无需第一版云端账号体系。

### 9.2 企业 API 集成

Staix 可以通过 HTTP API、MCP、Command 或自定义能力接入企业系统。

可集成对象包括：

- OCR 服务。
- 合同管理系统。
- 客户或主体查询接口。
- 知识库系统。
- 审批或工单系统。
- 内部数据服务。
- 文件转换和报告生成工具。

### 9.3 本地模型和私有化模型

对于数据敏感场景，Staix 可接入本地 OpenAI 兼容服务或企业私有化模型服务，例如 Ollama、LM Studio 或内部模型网关。

这种方式适合：

- 不允许业务材料出公网的场景。
- 需要在内网部署模型的企业。
- 希望控制推理成本的试点团队。
- 对模型供应商有合规限制的行业。

## 10. 对合作伙伴的开放点

Staix 可与合作伙伴在以下方向形成联合方案：

- OCR 和文档识别能力接入。
- 法务合同审查规则库。
- 行业知识库和审查清单。
- 企业系统 API 封装。
- 私有化模型和模型网关。
- MCP 工具生态。
- 智能体模板和行业工作流。
- 审计、合规和风控方案。

合作伙伴可以把自身能力封装为 Staix 的业务能力、任务模板、知识包或专用智能体，交付给最终企业用户使用。

## 11. 产品阶段说明

当前产品方向分为已落地基础能力和规划能力。

已落地或已进入第一阶段范围的能力包括：

- Windows 桌面客户端基础界面。
- 工作区选择和文件浏览。
- 本地环境展示。
- 模型配置管理。
- 业务能力配置管理。
- 智能体配置管理。
- 内置 Pi agent core 运行时链路。
- RPC 形态的 Agent Adapter。
- 会话发送和接收。
- 附件元数据与图片输入支持。
- 审计日志基础能力。
- 自动更新基础能力。

规划和后续增强能力包括：

- 更完整的 OCR Prompt 优化闭环。
- 合同审查工作流模板。
- 更强的批量样本评估。
- 子智能体能力。
- 企业集中管理和云同步。
- 更细粒度权限确认。
- 内核版本选择、更新和回滚。
- 面向行业的智能体模板市场。

| Tool | 智能体可以调用的工具能力。 |
| Skill | 带有使用说明、流程和边界的可复用智能体能力。 |
| MCP | Model Context Protocol，用于暴露外部工具能力的协议形态。 |
| Prompt | 给模型的任务指令或提取规则。 |
| 审计日志 | 记录智能体关键动作、工具调用、文件访问和执行结果的日志。 |

## 13. 一句话总结

Staix 石斧智能体把大模型能力、企业知识、业务工具和本地文件工作区整合为一个可配置、可审计、可扩展的桌面智能体工作台，帮助企业把 AI 从单次问答推进到可复用的业务流程自动化。
